# Stage Progression

Gamble Battle uses procedural chapters as the default campaign path from Chapter 1 onward. Every chapter keeps the same 5-stage cadence:

1. Creep reward round
2. Normal RGA challenge/puzzle
3. Normal RGA challenge/puzzle
4. Boss
5. Mirror fight against the board the player took into the boss fight

Core constants live in `scripts/game/progression/progression_config.gd`. `PROCEDURAL_START_CHAPTER` is `1`, and `EASIEST_REFERENCE_RATING` anchors the generated target-rating curve.

Enemy composition lives in `scripts/game/progression/roster_catalog.gd`. The old authored chapter map remains in the catalog as a reference source, but default gameplay routes Chapter 1 and later through generated specs.

`scripts/game/progression/endless_chapter_generator.gd` builds generated StageSpecs by difficulty rating. `RosterCatalog` caches those specs in chapter/stage order so planning preview and combat receive identical generated boards. Normal stages include `rga_challenge` metadata, boss stages are generated from the same difficulty budget system, and mirror stages use the boss-entry board snapshot. Generated normal/boss difficulty includes raw unit level rating, active enemy trait pressure, and generated completed-item pressure when item loadouts are assigned. Trait and item pressure are priced through `scripts/game/progression/difficulty_rating_model.gd`, and generated rules expose `difficulty_model_version` so audits can catch stale specs. Item-bearing generated boards expose `rules.items`, `rules.item_pressure_rating`, and `rules.item_loadout_summary`; runtime spawning applies those loadouts through the stage rules path.

The current generated stage multipliers are intentionally conservative for natural campaign progression: creep `0.35`, first RGA `0.70`, second RGA `0.80`, boss `0.85`, mirror target `1.05`. Creep rounds are generated by seed and target rating from Chapter 1 onward and now contain at least two lowercase creep reward enemies so the player can earn more than one component drop from the round. If a raw creep board overshoots its target, the generator emits a generic `rules.stat_scale` so `StageRuleRunner` scales combat stats down to the target without relying on a fixed Chapter 1 opener.

Player-facing combat launched through `CombatManager` uses a runtime failsafe of `105s` hard timeout and `45s` no-progress timeout. Stalled procedural matchups resolve as tie/refund before the UI can remain battle-locked for several minutes, while RGA probes that instantiate `CombatEngine` directly keep their own configured simulation windows.

Boss rounds still use one featured enemy unit, but generated boss stat inflation is capped so ordinary low-cost units do not get scaled into unwinnable raid bosses. The first boss caps at `2.25x` stat scale, later boss caps rise slowly by target band and unit cost, and the hard cap is `3.25x`. When that cap prevents a one-unit boss from reaching the requested budget, the StageSpec reports the playable effective `target_rating` and preserves the original curve budget in `requested_target_rating`.

Generated mirrors are exact copies of the board the player took into the boss fight. The mirror snapshot preserves unit order, unit ids, levels, combat stats, equipped item ids, and captured board formation. Mirror specs keep target/difficulty metadata for preview and audit context, but they do not scale the copied board or strip copied items.

Player-facing naming remains the original chapter pattern. `ChapterCatalog.display_name_for()` returns `Chapter N` for Chapter 1 and all later generated chapters; the top bar and logs should not show an endless-mode label.

Mirror fights use `scripts/game/progression/mirror_board_store.gd`. The combat manager snapshots the player's board when the boss fight starts, then the mirror rule applies that snapshot to the next stage's enemy team. When the arena is configured, the manager preserves the copied formation on the enemy side so the player is fighting the board they just proved with.
